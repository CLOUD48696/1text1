# 本轮开发 Prompt

编写日期：2026-11-18。作者为 Codex，依据用户“Prompt 你来编写，尽量拟人；其他任务你自己完成”的要求制定。以下是本轮将实际采用的原始任务指令，不冒充早期用户输入或 Claude Code 日志。执行结果与对应提交在完成后补录。

## P01 · SDD：把讨论列表的边界说清楚

> 我们的首页现在只拿最新 100 场，旧的讨论还在运行时可能找不到。请先把这个问题拆清楚：筛选应该在数据库查询时完成，分页发生在筛选之后，而不是把第一批数据拿到页面再筛。保留已有列表响应结构，明确全部、进行中、已结束分别包含哪些状态，以及 cursor 的含义。数据库还是 SQLite，别为了这个功能引入新服务；先写下契约和可观察的验收条件，再动业务代码。

意图：避免“按钮有了，旧讨论还是找不到”。主要边界是筛选与分页顺序，以及前后端状态定义一致。

## P02 · TDD：先证明旧讨论不会被漏掉

> 先写能暴露问题的测试。准备一场较早创建、仍可加入的讨论，再放入超过 100 场更新的已结束讨论；选择进行中时，旧讨论必须出现。再检查跨页没有重复或遗漏，最后一页没有下一页，非法筛选值会被拒绝。先运行看到真实失败，再提交测试；不要把测试写成逐行复述实现。

意图：验证用户能找到讨论，而非仅验证新增参数存在。保留本轮实际红灯与后续通过结果。

## P03 · DDD：让分页像页面的一部分

> 接着把首页接上新的列表接口。保持现有浅色圆桌界面的风格，用清楚的上一页、下一页和页码就够了，别让用户理解 offset。切换分类回到第一页，加载时避免重复点击；空列表、请求失败和重试也要有清楚反馈。用户快速切换筛选时，较慢的旧请求不能把新列表盖回去。手机上按钮要能点，长话题不能撑出横向滚动。

意图：让分页和筛选形成完整交互，并处理异步响应交错。页面不暴露数据库术语。

## P04 · 模型提示词：让人听起来像在交流

> 请调整主持人和专家的提示词，让这场讨论像几个认真听彼此说话的人。专家先接住前面一个具体观点，再给自己的理由或条件，不要每次都从“从我的专业角度来看”开始；没新东西就等一等，不必为了热闹硬反对。主持人追问争议中的前提，不要把每段发言复述一遍。仍然保持每次一到两句、人物虚构、不编数据、不展示隐藏推理，JSON 只用于后台协议。最后区分“确实有证据的共识”和“还没谈清楚的问题”，别替大家强行达成一致。

意图：优化衔接、措辞与观点差异，同时保持输出契约。自然程度需要真实模型验证，不能凭改了文字就宣称有效。

## P05 · E2E：从用户路径检查一遍

> 现在用真实后端和独立测试数据库检查。除了原来的创建、确认、讨论、刷新和双房间隔离，还要实际点首页筛选和翻页，确认旧讨论可见、切换分类回到第一页、页面没有重复卡片。桌面和手机都跑；如果出现错误，先看请求和页面状态，修完再验证受影响的流程。模型替身和真实 DeepSeek 分开记录，不要把 Demo 的结果写成真实模型已通过。

意图：从用户操作确认接口、组件与状态归并协同工作，不用浏览器假响应绕过后端。

## P06 · 交付：让评审拿到就知道怎么看

> 最后按交付清单收尾。把复盘排成一到一点五页的可阅读附件，保留真实使用的工具和遇到的问题；Prompt 文档说明哪些是本轮新写并执行的，不补造以前的记录。打包源码、初始化、种子、测试和文档，排除 Key、数据库、依赖目录和缓存，检查压缩包内容并写清对应 Git 版本。真实模型没有配置就如实列为待验，人工验收也留给用户；不要为了看起来完整就把状态全打勾。

意图：交付内容可复现、可检查且不泄露本机配置。页数、包内容和 Git 状态均需实际验证。
