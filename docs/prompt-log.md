# 早期 Prompt 与过程摘录

本文件保留早期开发的可追溯摘录。本轮按用户要求新编写并执行的六段任务指令见[本轮开发 Prompt](development-prompts.md)，覆盖 SDD、TDD、DDD、E2E。两者来源不同：以下公开阶段说明不是早期完整原始输入，也不是 Claude Code 导出日志。

实际开发工具为 Codex。应用运行时提示词独立位于 [prompts.py](../backend/app/llm/prompts.py)，它描述如何生成嘉宾、意图、发言和观点，不等同于指导编码的开发 Prompt。

## 1. 来源与记录标准

- 用户原话：来自本聊天的实际输入，保留引文。
- 阶段说明：沿用开发过程中已记录的 Codex 公开实施说明，标注性质，不冒称用户输入。
- 提交与验证：引用实际 Git 产物；红灯、通过数和模型调用以验证记录为准。
- 后续原始记录：需来自可追溯的会话导出或原始工具输入，不能事后编造。

## 3. 已记录的阶段说明

下面六段引文是公开阶段说明摘录，不是六条已满足原题的原始核心 Prompt。每段保留实施意图、问题或修正，以及关联提交。

### S01 — SDD：数据与接口契约

> 第一步按 SDD 落实数据与接口契约：讨论按 ID 隔离，后台任务独立于浏览器连接，所有模型结果先校验再入库。没有 API Key 也能运行明确标注的演示模式。

意图：先定义状态边界、模型输出结构和事件恢复。实现中将业务写入和事件追加放入同一事务，防止数据与推送不一致。关联提交：1819b48、5f54be3。

### S02 — DDD：组件与页面

> 接下来按 DDD 阶段完成首页、阵容确认和演播厅 Demo：先验证页面和交互，再接入真实后端事件。

意图：先验证产品结构；按题目口径，DDD 指组件/页面开发。实际改用原生 CSS，接入后端后移除静态预览分支并拆分组件。关联提交：1819b48、1efc3f1。

### S03 — TDD：核心调度

> 接着先写调度器的失败测试，验证反驳优先级、公平性和无人申请时的行为。

意图：把自主发言转成可验证的仲裁规则。首次运行因 app.services 不存在失败，测试先提交，实现后 9 项核心测试通过。关联提交：5bc13cb、5f54be3。

### S04 — 集成验证：隔离与可靠性

> 下一步会验证实现是否通过，并补齐重复启动、跨讨论引用和断线补发测试。

意图：防止多场串台、刷新重启和历史丢失；补充超时、无人发言、预算和异常输出回归。该阶段包含实现后的测试补充，不全部标为严格 TDD。关联提交：5f54be3、9309db8。

### S05 — E2E：浏览器闭环

> 现在进入完整流程验证：创建讨论、确认阵容、实时发言、观点提炼、总结和刷新恢复；同时检查超时、无效模型输出等异常分支。

意图：在真实后端上验证完整用户流程。页面检查发现演示观点关键词漏匹配后修正并增加回归；桌面和手机共 6 项 E2E 通过。关联提交：1efc3f1、9309db8。

### S06 — 模型集成：DeepSeek

> 真实模型先只接 DeepSeek。我会核对它的官方接口和可用模型配置，并把 `.env.example`、启动校验和说明统一到 DeepSeek；Key 仍只保存在后端。

意图：落实单供应商范围。处理空白、截断及无效 JSON，并以模拟 HTTP 响应检查请求和隐藏推理隔离；没有真实请求成功记录。关联提交：9309db8。

## 4. 早期完整会话的取证边界

至少五段真实核心开发输入需要覆盖 SDD、DDD、TDD、E2E，并为每段附 1–2 句意图、挑战或纠正说明。建议记录字段为：

| 字段 | 要求 |
| --- | --- |
| 来源 | 实际会话日期、工具、可追溯的原始记录位置 |
| 原始 Prompt | 完整保留实际输入；摘要需另标，不替换原文 |
| 阶段 | SDD / DDD / TDD / E2E |
| 说明 | 当时意图、遇到的问题、如何修正 |
| 产物 | 相关提交、文件或实际验证结果 |

本轮六段新指令已有独立文档与执行记录；它们不填补早期完整会话导出的缺失。若评审要求初始全过程原始会话，应另提供真实导出，不用本轮指令替换历史。交付状态统一见[交付清单](delivery.md)。
