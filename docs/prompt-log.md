# 开发阶段摘录

以下摘录按阶段关联实现与 Git 提交。六段开发指令见[开发 Prompt](development-prompts.md)，圆桌运行时提示词见 [prompts.py](../backend/app/llm/prompts.py)。

## S01 — SDD：数据与接口契约

> 第一步按 SDD 落实数据与接口契约：讨论按 ID 隔离，后台任务独立于浏览器连接，所有模型结果先校验再入库。没有 API Key 也能运行明确标注的演示模式。

意图：先定义状态边界、模型输出结构和事件恢复。实现中将业务写入和事件追加放入同一事务，防止数据与推送不一致。关联提交：1819b48、5f54be3。

## S02 — DDD：组件与页面

> 接下来按 DDD 阶段完成首页、阵容确认和演播厅 Demo：先验证页面和交互，再接入真实后端事件。

意图：先验证产品结构；按题目口径，DDD 指组件/页面开发。实际改用原生 CSS，接入后端后移除静态预览分支并拆分组件。关联提交：1819b48、1efc3f1。

## S03 — TDD：核心调度

> 接着先写调度器的失败测试，验证反驳优先级、公平性和无人申请时的行为。

意图：把自主发言转成可验证的仲裁规则。首次运行因 app.services 不存在失败，测试先提交，实现后 9 项核心测试通过。关联提交：5bc13cb、5f54be3。

## S04 — 集成验证：隔离与可靠性

> 下一步会验证实现是否通过，并补齐重复启动、跨讨论引用和断线补发测试。

意图：防止多场串台、刷新重启和历史丢失；补充超时、无人发言、预算和异常输出回归。该阶段包含实现后的测试补充，不全部标为严格 TDD。关联提交：5f54be3、9309db8。

## S05 — E2E：浏览器闭环

> 现在进入完整流程验证：创建讨论、确认阵容、实时发言、观点提炼、总结和刷新恢复；同时检查超时、无效模型输出等异常分支。

意图：在真实后端上验证完整用户流程。页面检查发现演示观点关键词漏匹配后修正并增加回归；桌面和手机共 6 项 E2E 通过。关联提交：1efc3f1、9309db8。

## S06 — 模型集成：DeepSeek

> 真实模型先只接 DeepSeek。我会核对它的官方接口和可用模型配置，并把 `.env.example`、启动校验和说明统一到 DeepSeek；Key 仍只保存在后端。

意图：落实单供应商范围。处理空白、截断及无效 JSON，并以模拟 HTTP 响应检查请求和隐藏推理隔离；没有真实请求成功记录。关联提交：9309db8。
