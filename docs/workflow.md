# 开发过程与工作流复盘

本项目实际由 Codex 辅助开发，应用侧接入目标为 DeepSeek。未使用 Claude Code，未完成真实 DeepSeek 调用验收；不将运行时模型适配等同于开发工具使用经历。本文为复盘正文，Git 演变证据保留在 Markdown 版本末尾。

## 1. 从需求到分阶段实现

开发按用户指定的流程推进：Git 与协作约定 → 产品方案和 Demo → 技术设计 → 编码与 AI 自测 → 人工验收。24 小时作为工作预算，不作为已经投入时长的记录。

先将题目拆成可检查的条件：阵容确认前不能开场，专家不能固定轮流，观点必须在过程中更新，讨论之间不得共享状态，刷新不能重新启动任务。产品需求定义用户可见行为，技术设计确定状态边界和数据流，API 契约明确前后端交互。

SDD 阶段定义讨论、嘉宾、消息、观点和事件，以及模型输出结构。DDD 按本题所指的组件/页面开发实施，先完成首页、阵容确认和演播厅 Demo，再替换为真实后端接口。前端采用原生 CSS，减少小型 MVP 的依赖和样式整合成本。

TDD 阶段先提交调度与证据校验测试；首次因实现模块不存在失败，再实现仲裁和校验。其他预算、异常与多讨论场景采用集成回归验证，未全部做到严格测试先行。E2E 使用真实 FastAPI/SQLite 与可控 DemoLLM，验证桌面、手机、刷新和隔离。真实模型验证另列，避免把替身通过解释成生成质量通过。

## 2. 实际问题与处理

**服务启动不等于网页可访问。** 曾出现进程显示监听但客户端连接超时。检查本地端口与 HTTP 后，在可连通的运行环境重启并确认首页返回 200，再进行浏览器检查。运行验证因此同时检查服务与用户入口。

**结构正确不等于观点正确。** Demo 的支持性发言采用了另一种措辞，提炼规则漏匹配，导致分歧缺失。根据页面检查修正规则，并增加种子证据回归测试。这说明引用 ID 有效仍不足以证明语义：真实模型的观点质量需要另做人工验收。

**快照和事件会交错。** 旧快照可能覆盖较新的 SSE 状态。状态归并加入讨论 ID 与序号校验，拒绝倒退；启动结果由持久化事件驱动，并在刷新及双讨论测试中验证。后台任务独立于观众连接，避免刷新触发重复运行。

## 3. 工程化 AI 开发的理解

AI 负责生成候选实现和语义内容，应用必须掌握生命周期、预算、校验和错误处理。角色、意图、发言、观点提炼分别设定输入输出边界，使模型失败可以定位和有界终止。

可追溯性与代码同样重要：Git 保留阶段提交，测试记录注明环境与实际结果，Prompt 记录区分用户原话、公开阶段说明和缺失的原始材料。本轮新增六段自然表达的开发指令并按阶段执行，分页保留了两项测试先失败、实现后通过的记录。真实模型与用户人工检查仍待完成，不因补齐附件就提前标为通过。
