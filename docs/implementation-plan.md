## 建议提交节奏

按实际产物提交，例如 `docs: define product and implementation plan`、`feat: add studio demo and API schemas`、`test: define discussion scheduling contracts`、`feat: implement discussion engine and events`、`feat: connect live studio`、`test: cover complete discussion flow`、`docs: finalize delivery and validation`。

不要为了满足列表创建空提交，或把最终代码拆成虚构的历史。每次提交前检查差异，排除密钥、本地数据库和构建产物。

## 人工验收清单（待用户执行）

1. 根据 README 在本地启动，能看出当前是 Demo 还是 live。
2. 输入自选议题，确认默认 4 专家和 1 主持人；确认前没有开场。
3. 观察至少一次针对前文的补充或反驳，以及主持人介入。
4. 发言人高亮、关注点与 Transcript 可区分，不出现内部 JSON/举手消息。
5. 讨论未结束时已经出现共识或分歧，证据来自当前讨论。
6. 刷新、另开页面加入同场讨论，历史一致且没有重新开场。
7. 新建第二场不同话题，两场各自运行，无串台。
8. 查看最终自然语言总结与保存的历史。
9. 调整窗口宽度，三类视口核心操作均可访问。
10. 检查测试结果、种子数据、Prompt 记录、Git 历史与复盘材料。
