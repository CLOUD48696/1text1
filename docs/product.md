# 产品方案与验收标准

## 1. 产品目标

用户输入一个议题和专家数量（默认 4 位专家，另加 1 位主持人），确认 AI 生成的阵容后，进入演播厅观看短回合、可互相回应的讨论。系统持续提炼共识与分歧，结束时主持人给出自然语言总结。

核心用户：需要多角度分析的知识工作者、评审方案的产品/决策人员、需要结构化讨论材料的教育/内容创作者。

成功体验：用户能明显看到不同立场之间的回应、补充和反驳，能区分正在发言与准备发言的专家，能在讨论结束前看到观点变化。

## 2. 用户流程

1. 首页查看已有讨论，可加入正在运行的讨论或查看历史记录。
2. 输入话题、选择专家数量，生成主持人和专家阵容。
3. 查看姓名、职业、Title、立场与专属颜色；确认后启动。生成失败时可重试。
4. 演播厅实时展示主持人与专家发言、状态以及共识与分歧。
5. 讨论达到预算后，由主持人总结；历史内容可再次查看。

拟定 MVP 专家人数范围为 2–6，可配置；这属于产品取舍，不是原始题目的明确上限。

## 3. 页面与 Demo

先做使用固定样例的交互 Demo，再对接真实 API。Demo 需明确显示“演示数据”，不把预设文本当作模型真实输出。

- 首页：品牌标题、话题输入、专家人数、生成按钮、讨论列表与状态。
- 阵容确认：主持人和专家卡片、立场说明、确认开始、返回修改；不增加复杂人物编辑器。
- 演播厅：顶部话题/阶段/连接状态，左侧嘉宾，中间 Transcript，右侧共识/分歧。

视觉方向：浅暖灰背景、白色卡片、深绿品牌色；专家使用互相区分的专属颜色。文字优先，轻量状态动画，不引入 3D 或语音资源。

布局要求：应用占据视口，桌面三栏按容器独立滚动；中等宽度缩窄侧栏；小屏用“现场 / 嘉宾 / 观点”标签切换。不能依赖整页滚动查看主要操作。

Transcript 自动跟随新消息，但用户滚动查看历史时暂停跟随，提供“有新发言”按钮。姓名、职业/Title 和颜色始终一致；举手、评分等内部事件不混入 Transcript。

## 4. 必做范围与验收

| 编号 | 功能 | 可观察的验收条件 |
| --- | --- | --- |
| P01 | 讨论首页 | 能列出至少 5 组种子讨论，能进入已有讨论 |
| P02 | 动态嘉宾 | 默认 4 专家 + 1 主持人，字段完整；用户确认前不运行 |
| P03 | 主持人 | 有开场、必要的追问/串联和最终自然语言总结 |
| P04 | 自主调度 | 专家根据当前 transcript 提交意图；不采用固定循环名单 |
| P05 | 短发言 | Prompt 要求每次 1–2 句，后端检查长度并限制异常长输出 |
| P06 | 专家状态 | 等待、准备、发言中可见；公开关注点简洁，不泄露隐藏思维链 |
| P07 | 实时观点 | 讨论进行中出现共识/分歧，并关联有效的原始发言 |
| P08 | 实时更新 | 无需刷新即可看到新增发言、状态与观点 |
| P09 | 多讨论隔离 | 同时运行两场时，消息、事件、状态、观点无串台 |
| P10 | 加入与恢复 | 新观众/刷新能恢复当前快照，不重复启动讨论，不重复显示消息 |
| P11 | 总结 | 结束展示主持人自然语言总结，不输出 JSON 原文 |
| P12 | 响应式 | 宽屏、普通桌面、小屏均可访问核心功能，各区域按设计滚动 |
| P13 | 异常可见 | 生成失败、模型超时、连接重试都有明确提示；无无限等待 |
| P14 | 运行方式 | 按 README 可初始化 SQLite 并启动本地前后端，密钥仅在后端 |

每个专家单独评估意图会带来模型调用开销。默认限制讨论轮数、最大专家发言数与总时长，实际默认值在真实模型测速后调整；页面不承诺未经测量的响应时间。

## 5. 范围控制

本轮不做登录/权限系统、多人共同编辑、语音合成、联网检索、文件知识库、向量数据库、支付、云发布或复杂崩溃续跑。

全部必做项通过后，优先增加“点击共识/分歧定位原始发言”。额外动画与模型供应商切换的优先级更低。

## 6. 种子数据计划

至少五组高质量话题，每组配置 1 主持人及 4 位立场不同的虚构专家：

1. 小型软件团队应该优先使用 AI 编程工具还是增加招聘？
2. 企业是否应实行每周四天工作制？
3. 高校课程应如何允许学生使用生成式 AI？
4. 初创产品应该先增长还是先盈利？
5. 城市中心是否应限制私人汽车通行？

种子数据应覆盖待确认与已结束状态；实时运行状态由真实任务产生，不预置伪造的运行中记录。初始化脚本可重复执行，不重复插入种子。

## 7. 待核实的作业口径

原始材料允许任意 Vibe Coding 工具，但复盘条目点名 Claude Code + DeepSeek V4 Pro。应核实是否强制指定；当前实际使用的是 Codex，交付材料必须如实写明。无论此项是否确认，都可以继续本地工程和演示模式开发。
