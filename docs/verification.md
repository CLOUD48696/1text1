## 3. 真实 DeepSeek 联调（2026-11-19）

DeepSeek 官方模型列表返回 HTTP 200。使用账号可用的 deepseek-v4-pro 通过 FastAPI 创建讨论，话题为“小团队要采用四天工作制，应先试点还是直接推广？”。本次使用独立临时 SQLite、2 位专家、最多 3 次专家发言。主持人另计。

| 检查 | 观察结果 |
| --- | --- |
| 第一次尝试 | 阵容生成和开场成功，讨论阶段进入 failed。未收到供应商 HTTP 错误，具体失败原因未确认。 |
| 第二次尝试 | 阵容耗时 4.3 秒，确认前有 3 位嘉宾、0 条发言。确认后约第 6 秒（从创建算起）观察到开场。 |
| 发言和提炼 | 主持人及专家共 6 条发言，讨论中已出现观点，最终 2 条观点的证据 ID 均属于本场消息。专家曾生成三句话，经现有校验和重试后发表短发言。 |
| 总结和事件 | 总结讨论了客户响应基线、试点范围及人才留存指标。43.4 秒完成，SSE 回放含 34 条本场事件，最后一条为 discussion.completed。 |

## 4. 用户验收

2026-11-19，项目负责人确认功能完成，整体验收状态更新为**已完成**。下表列出本次验收范围。

同题故障复测（2026-11-19）：数据库中“ai时代，人类是否还需要工作”的原讨论只有主持人开场。事件停在首位专家准备发言，旧版没有保留底层异常类型。模拟专家连续两次返回三句话，复现了旧版在同一阶段终止的行为。修复后该用例和后端全套 30 项测试通过。

在本地演播服务上使用同一话题、4 位专家和真实 DeepSeek 配置重新创建讨论。约 88 秒完成，共 11 条发言，最终保留 3 条共识和 3 条分歧，并生成主持人总结。浏览器打开回看页面并刷新后，发言和观点数量一致。
